# v0.3.6 动作回退修正与纯 CPU 动画可行性测试

日期：2026-10-25（Asia/Shanghai）。环境：Apple M4、16 GB 内存、桌面 Chrome；未使用 GPU / MPS。

## 修正与验收

- 桌面 Chrome 实点“吃一口”：舞台在动作阶段显示同一原创角色拿饼干的姿势，之后进入回答；这证明按钮能切换姿势，但不是连续动作。
- 发现并修复待机视频会压掉动作姿势的问题：缺少动作视频时，待机视频循环播放，静态姿势仍会显示在上层；只有对应动作视频才作为动作片段播放。
- 工作台和舞台明确标注静态姿势、连续动作视频缺失，不再把静帧描述为真实动作；舞台卡片会说明当前无法连续运动。
- 11 项自动化测试通过；`node --check`、`git diff --check` 通过。

## 纯 CPU 运动模型测试

- 在 `/tmp` 隔离环境安装 LivePortrait 官方 macOS 依赖和公开权重，明确传入 `--flag-force-cpu --no-flag-use-half-precision`。模型加载成功，没有启用 MPS/GPU。
- 对 3.12 秒、78 帧片段运行到 47% 时已耗时 4 分 43 秒；持续高 CPU 与约 2–4 GB 内存占用。为避免长时间占用机器而停止；按当前速度完整生成约需 10 分钟，远低于直播实时速度。
- 用现有姿势图做淡入淡出视频原型，出现明显的双手重影和脸部叠影，因此不加入产品。
- 结论：在用户限定的全离线、无 GPU 条件下，本项目目前只能做静态姿势示意，或播放预先准备的同角色动作视频；不能由单张照片即时生成自然的真人动作。

## 仍待完成

- 用户确认目标是参考直播里的数字人，但没有可用截图/视频素材；按用户最新要求保留原创角色和直播氛围，不声称 1:1 复刻。
- 抖音真实弹幕和正式推流未接入。连续吃喝、挥手与自然口型仍需要同一原创角色的动作视频素材；本轮 CPU 模型速度不支持实时驱动。
- 抖音直播伴侣 Mac 版已打开并确认显示扫码登录页；未扫码、未选择窗口、未开始直播。登录后的窗口采集、声音与真实推流仍待账号所有者完成扫码后验收。
