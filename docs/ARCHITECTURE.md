# 本地工作方式

```text
手动弹幕 / 本机 HTTP 事件
          ↓
队列（去重、30 条上限、默认人工审核）
          ↓
单一表演调度线程
          ├─ 回答生成：默认规则 / 可选本机 Ollama
          ├─ 语音：macOS say → afconvert → WAV
          └─ 状态：准备 → 动作 → 说话 → 待机
                       ↓ SSE
        工作台静音预览 + 独立直播画面（启用声音）
                       ↓
          用户配置的窗口捕获 / 音频捕获
```

只服务一个本机直播场景，后端不为每个观众生成一路视频。素材是本地 MP4/WebM，浏览器使用视频解码和 CSS/SVG 绘制；不调用 GPU 模型推理。浏览器/系统自身可能使用硬件加速进行普通视频播放，不等于需要独立显卡或运行 AI GPU 模型。

## 边界

- Python 标准库 `ThreadingHTTPServer`，只绑定回环地址，不作为公网服务部署。
- Host/Origin 和 Fetch Metadata 校验用于阻止 DNS rebinding 和跨站写入；不开放 CORS。
- 浏览器上传是原始字节流，随机文件名，FFprobe 校验视频流、编码与时长。静态路径限同层文件，支持单段 Range。
- 前端观众文本使用 `textContent`，不插入 HTML；页面不加载 CDN、外部字体或外部脚本。
- 队列操作与 SQLite 写入由同一锁保护。配置校验通过后原子更新。当前任务通过取消事件中断，Mac 语音子进程随之结束。
- 服务端时间驱动表演，不以每个浏览器作为调度主节点。断线重连恢复最新状态，音频尝试从当前时点续播。
- 精细语音/视频帧同步、消除浏览器缓冲差异、云端模型流式文本、自动弹幕采集属于后续工作。

## 后续模型 API 的接法

保留队列与表演层，只替换 `Studio.reply(job, config)`，返回中文文本即可；`speech()` 和素材状态切换继续工作。建议下一步把提供方抽成单独模块，增加环境变量密钥、模型超时、流式分句和成本统计。当前版本不读取任何云端密钥、不发云请求。

Mac 原生声音以后也可单独替换为在线 TTS，但这与聊天模型 Token 接入是两件事。写实视频动作仍由素材库提供，接模型 API 不会自动解决手部动作或精确口型。
